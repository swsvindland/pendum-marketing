# vector-marketing

The marketing site for the Vector app series: OmegaFyt (the subscription, account-based app) and the four one-time
purchase, offline apps (Vector Body, Vector Lift, Vector Macros, Vector Hydration), plus free fitness calculators.
Next.js 16 App Router, React 19, Tailwind v4, TypeScript, pnpm. Local git only for now.

```sh
pnpm dev            # http://localhost:3000
pnpm check          # typecheck, lint (with the token drift and page-code rule check), unit tests
pnpm build
pnpm tokens:pull    # copy the canonical kit's tokens.json in and regenerate
```

## The Vector kit, web edition (`src/vector`)

The design system is `../vector-design` (spec: `../vector-design/kit/docs/design-system.md`). That kit is React
Native on heroui-native; `src/vector` is its web re-creation on **HeroUI v3 for the web** (`@heroui/react`, React
Aria underneath), with the same rules, names and tokens. HeroUI supplies behaviour and accessibility, the kit
supplies the look, exactly as on native. Never edit `../vector-design` from here.

- `src/vector/tokens.json` is a snapshot of the kit's, and it is a HeroUI theme: the same variable names
  (`--accent`, `--surface`, `--field-background`, `--radius`…). `tokens.css` (generated by `scripts/vector-web.mjs`,
  do not edit) restates them unlayered over HeroUI's defaults, light, dark (system or `data-theme`) and
  `prefers-contrast: more`. `icon-paths.ts` (generated) holds the Ionicons glyphs.
- `globals.css` imports `@heroui/styles`, then `tokens.css`, then `components.css`: the kit's corrections to
  HeroUI slot CSS (no press scale, 44 minimum controls, flat radius, the field label and error look, fade-only
  overlays, accordion row geometry). HeroUI's CSS is in `@layer components`, so utilities still win over it.
- Page code never imports `@heroui/react` or `@heroui/styles`: it uses the kit. `pnpm lint` runs
  `vector-web.mjs check`, which fails on raw HeroUI imports, size/weight/case/tracking/shadow/radius classes,
  Tailwind palette colours, gradients and hex in page code (`src/app`, `src/components`, `src/calculators`).
- Type is a role, never a size: `type-hero type-display type-h1…h4 type-lead type-body type-body-strong type-small
  type-caption type-field-label type-button type-label type-readout-xl|l|m|s|xs`. Prefer the components: `Text`,
  `Heading`, `Note`, `Label`, `Value`, `Meta`. A rare weight change is `[font-weight:500]`.
- Colour is a token utility: `bg-background`, `bg-surface`, `bg-surface-secondary`, `bg-surface-tertiary`,
  `text-foreground`, `text-foreground-secondary`, `text-muted`, `text-tint`, `border-border`, `border-separator`,
  `border-border-strong`, `bg-accent` + `text-accent-foreground`, `text-success|warning|danger`, `bg-cat-1…3`.
  Shape: `rounded-control|panel|mark` (and `rounded-full` for the 6pt status dot).
- Entry points. `@/vector` is server-safe and imports no `@heroui/react` code: `ButtonLink` (HeroUI's button look
  on a Next link), `LinkButton`, `Panel` (+ `.Header .Title .Description .Body .Footer`), `ReadoutRow`, `Rule`,
  `Callout`, `ErrorText`, `Status`, `Meter`, `ListRow`/`RowList`, `SystemState`, `Icon`, `AppIcon`, the text
  components. HeroUI-backed parts have their own entry points, so a page ships only what it renders:
  `@/vector/button` (`Button` with `onPress`, `IconButton`), `@/vector/disclosure` (`Disclosures`, HeroUI Accordion,
  for FAQs), and the client inputs `@/vector/form/field` (HeroUI TextField), `/select` (HeroUI Select),
  `/choices` (HeroUI RadioGroup as the segmented control) and `/chip-row` (HeroUI CheckboxGroup). Client files
  import leaf modules.
- Fonts: `src/fonts/*.ttf` are the kit's files; the site serves WOFF2 subsets built from them by `pnpm fonts`
  (`scripts/fonts.mjs`). Rebuild them when the site gains characters outside the subset.
- Gallery of every component: `/kit` (not indexed).

## Rules that pages must follow (design-system §1, §2.4, §10)

1. Sterile before beautiful: white canvas (near-black at night), 1pt rules and alignment. No shadows, gradients,
   tinted blocks, illustrations, stock photos or emoji. Grey out the cyan and the page still reads as Vector.
2. Cyan `#22D3EE` (`bg-accent`) is only a fill with `#071017` on it: the one primary button per page, a selected
   option, a live state (3pt rule), progress toward the page's one hero goal. Text, links, lines and focus use
   `text-tint`/`border-tint`. Never cyan text on white, never white on cyan, never a 1–2pt cyan line.
3. Language in Inter, measurement in Plex Mono: every number with a unit, count or time goes through `Value`.
   Units are smaller and muted. Mono eyebrows (`Label`) carry live context or DOMAIN / OBJECT ("Record / Weight"),
   never a restatement of the heading.
4. Rectangles only: 4px controls and panels, 2px marks. App icons keep the system's mask (`AppIcon`).
5. One primary action per page. Everything else is secondary, ghost or a `LinkButton`.
6. Every value is stated in text; a meter, colour or dot never carries meaning alone.
7. Copy voice: short, declarative, present tense, sentence case everywhere (CSS uppercases labels), no
   contractions, no exclamation marks, no emoji, no "please", buttons are verb + object. No hype ("revolutionary",
   "seamless", "powerful", "ultimate"), and no speed words ("fast", "instant") the apps cannot measure.

## Content rules

- `src/content/apps.ts` is the single source for app copy; `docs/sources/app-facts.json` is the verified fact
  sheet it is written from (each claim has evidence in the app repos). Claim only what is shipped. Anything in a
  fact sheet's `notYetShipped` is never claimed; its `caveats` travel with the claims they qualify.
- No prices, store links, trial lengths, domains or contact addresses are invented. `site.ts` and each app's
  `stores`/`price` stay null until the owner supplies them; the UI renders "Coming soon" or the model in words.
- OmegaFyt subscriptions are bought only in the iOS and Android apps. The four Vector apps have no account, no
  server and no analytics; records live in a database on the phone. Do not say data "never" leaves the phone:
  Health sync is opt-in, OS device backups may include it, and backups go where the user saves them.

## Calculators

- Math lives in `src/lib/calc/<slug>.ts`, pure and unit-tested in `<slug>.test.ts` (vitest) with published
  reference values. It matches the apps where an app implements the same thing (`docs/sources/formulas.json`).
- Each calculator is `src/calculators/<slug>/page.tsx` (server: `CalculatorFrame` with intro, method, sources,
  caveat) and `tool.tsx` (client: `ToolLayout` and `Formula` from `../shared/tool-layout`, inputs from
  `../shared/fields`, results from `../shared/results`). Its route is `src/app/calculators/<slug>/page.tsx`, a
  static page per calculator, so it ships only its own tool; `src/calculators/registry.ts` gives routes their
  metadata from `src/content/calculators.ts`, the one source for titles, descriptions, lists and the sitemap.
- Inputs start empty; results show `EmptyResult` until valid. Canonical units inside the math (kg, cm, mL); the
  shared `useUnits()` choice converts at the edges. Errors say what is wrong and the valid range.
- Nothing typed into a calculator is sent anywhere. Only the unit choice (and the site's appearance) is remembered,
  in this browser's localStorage.
